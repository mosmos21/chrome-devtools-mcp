# トラブルシューティング

## 一般的なヒント

- `npx chrome-devtools-mcp@latest --help` を実行して、MCP サーバーがマシン上で動作するかテストしてください。
- MCP クライアントがターミナルと同じ npm と node のバージョンを使用していることを確認してください。
- MCP クライアントを設定する際、`npx` に `--yes` 引数を使用してインストールプロンプトを自動承認するようにしてください。
- `chrome-devtools-mcp` サーバーの出力から特定のエラーを見つけてください。通常、クライアントが IDE の場合、ログは出力ペインにあります。

## 特定の問題

### `Error [ERR_MODULE_NOT_FOUND]: Cannot find module ...`

これは通常、サポートされていない Node バージョンが使用されているか、`npm`/`npx` のキャッシュが破損していることを示します。キャッシュをクリアし、`chrome-devtools-mcp` をアンインストールしてから再インストールしてください。以下を実行してキャッシュをクリアします:

```sh
rm -rf ~/.npm/_npx # 注意: これにより他のインストール済み npx 実行可能ファイルも削除される可能性があります
npm cache clean --force
```

### `Target closed` エラー

これはブラウザを起動できなかったことを示します。Chrome インスタンスが実行されていないことを確認するか、実行中の場合は閉じてください。最新の安定版 Chrome がインストールされていること、および[システムが Chrome を実行できること](https://support.google.com/chrome/a/answer/7100626?hl=ja)を確認してください。

### 仮想マシン (VM) とホスト間のリモートデバッグが失敗する

VM 内の DevTools をホスト上で実行されている Chrome に接続する場合、ホストヘッダー検証により Chrome がすべてのドメインを拒否します。SSH 経由でポートをトンネリングすると、この制限を回避できます。VM 内で以下を実行します:

```sh
ssh -N -L 127.0.0.1:9222:127.0.0.1:9222 <user>@<host-ip>
```

VM 内の MCP 接続を `http://127.0.0.1:9222` に向けると、DevTools はホスト検証をトリガーせずにホストブラウザに到達できます。
